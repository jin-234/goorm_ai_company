# 백엔드 개발 계획 (Vercel)

「AI 상사 가상회사」를 **Vercel에 배포하는 웹 서비스**로 개발한다.
심사 기준(제출한 배포 주소에서 핵심 기능이 동작해야 함)에 맞춰, 화면과 서버를 배포 주소 하나로 제공한다.

## 1. 기술 구성

| 구성 요소 | 선택 |
| --- | --- |
| 실행 환경 | Vercel 배포 주소 하나 (Next.js) |
| 화면 | 브라우저(Next.js). 일반 화면으로 흐름을 먼저 완성하고 3D는 나중에 붙임 |
| 규칙 엔진 | TypeScript 순수 로직 (`src/lib/office`) |
| 서버 | Next.js API 라우트 = Vercel 함수 (`src/app/api`) |
| 저장 | **Supabase Postgres** `offices` 테이블, 참여자당 JSONB 한 줄 (Transaction pooler 연결) |
| AI | Upstage Solar. 키는 Vercel 환경변수 `UPSTAGE_API_KEY` (브라우저로 보내지 않음) |
| Solar 없을 때 | 서버 안 규칙(PTParser)으로 초안, 정해진 문구로 주간 답장 |
| 음성 전사 | 미정. **글 입력이 기본 경로**, 클라우드 STT는 붙일 자리만 둠(5장) |
| 착석 판정 | 브라우저 안에서 판정하고 결과(`present/absent/cameraOff`)만 서버로 보냄 |
| 가상 시계 | 요청이 올 때 흐른 실제 시간만큼 진행(3장) |

규칙 엔진이 다루는 것: 출근·지각·결근 후보, 점심 1시간·자리 비움 15분, 18:00 퇴근 점검 분기,
19:00~22:00 추가근무, 이월(처음 날짜 유지·횟수 증가), 보충근무 미이행, '다음 정각',
금요일 주간보고, 사내 메일 문구.

## 2. 구조

```
src/
├── lib/office/        규칙 엔진 (화면·DB·네트워크와 무관한 순수 로직)
│   ├── time.ts          KST 날짜·시각, DayKey, Clock
│   ├── rules.ts         근무 규칙 값, OfficeError
│   ├── models.ts        업무·초안·허용 시간·근태 기록·메일·주간보고 타입
│   ├── office.ts        Office 상태 기계 (출근 → 아침 PT → 근무 → 점검 → 추가근무 → 퇴근)
│   ├── seat-status.ts   자리 상태와 단계 한 줄 문구
│   ├── mail-templates.ts 사내 메일 문구
│   ├── pt-parser.ts     Solar 없을 때 전사문 → 초안
│   └── organization.ts  조직도 8명
├── lib/solar/         Upstage Solar 클라이언트, 주간보고 기본 답장
├── lib/server/        저장소, 세션(시계 맞추기), 행동 적용, 화면용 상태
└── app/api/           Vercel 함수(라우트)
```

요청 하나의 흐름: **쿠키로 참여자 찾기 → DB에서 상태 읽기 → 가상 시계 맞추기 → 규칙 실행 → 저장 → 화면용 상태 응답**.
규칙을 어기면(예: 출근 전에 업무 확정) 저장하지 않고 409와 한국어 안내 문구를 돌려준다.

## 3. 가상 시계

- 처음 접속하면 **실제 오늘이 속한 주의 월요일 08:55**에서 시작한다.
- 서버는 계속 떠 있지 않으므로, 요청이 올 때 **마지막 요청 뒤 흐른 실제 시간만큼** 시계를 보낸다.
- 화면은 `GET /api/office`를 **몇 초(권장 5~10초)마다** 불러 시계와 상태를 맞춘다. 초 단위 시계 표시는 화면에서 직접 흘린다.
- **2분 넘게 요청이 없으면** 브라우저를 닫아 둔 것으로 보고 그 사이 시간은 흘리지 않는다.
- '다음 정각'은 `skipHour` 행동. 18:00·19:00·22:00 경계에서 멈춘다.

## 4. 확인 방법

```bash
npm install
npm test          # 시험 94개 (규칙 엔진·PTParser·Solar·서버)
# Postgres 저장소 시험은 TEST_DATABASE_URL(예: Supabase 개발용 DB)이 있을 때만 돈다
npm run build     # Vercel과 같은 빌드
npm run dev       # http://localhost:3000, DATABASE_URL 없으면 메모리 저장
```

## 5. 남은 일

| 순서 | 일 | 메모 |
| --- | --- | --- |
| 1 | **Supabase 연결** | Vercel 대시보드 → Storage → Supabase 추가하면 `POSTGRES_URL`이 자동으로 들어간다. Supabase를 직접 만들었다면 Connect → Transaction pooler 주소(포트 6543)를 `DATABASE_URL`로 넣는다. `UPSTAGE_API_KEY`도 환경변수에 추가. 테이블은 첫 요청 때 자동으로 만든다(`db/schema.sql`과 같음). |
| 2 | 화면(프론트) | `docs/backend/API.md`대로 붙인다. 출근 → 아침 PT → 체크리스트 → 퇴근 점검 흐름을 일반 화면으로 먼저 완성하고 3D는 나중에. |
| 3 | 음성 전사 | 기본은 **글 입력**. 클라우드 STT를 붙이면 결과 글을 `setTranscript` 또는 `/api/office/draft`의 `transcript`로 넣는다. 실패하거나 권한이 없으면 글 입력 화면으로. |
| 4 | 착석 판정 | 브라우저(예: MediaPipe)에서 판정해 상태가 바뀔 때만 `observePresence`로 보낸다. 영상은 서버로 보내지 않는다. 카메라 없이 시연할 때는 버튼으로 같은 값을 보낸다. |
| 5 | 피드백 반영 | 관리 강도 선택, 희망 직무 연결, AI/운영자 역할 정리 등은 규칙 엔진에 기능을 더하는 방식으로(아래). |
