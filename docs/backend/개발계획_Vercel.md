# 백엔드 개발 계획 (Vercel 배포판)

원본 기획서 「AI 상사 가상회사 프로젝트 기획서 (맥 앱판)」의 규칙을 그대로 따르되,
**맥 앱 하나**로 만들던 구조를 **Vercel에 배포하는 웹 서비스**로 바꾼다.
현직자 피드백의 가장 큰 지적("배포된 주소로는 서비스에 접근할 수 없다")을 해결하는 것이 목적이다.

## 1. 무엇이 바뀌었나

| 구성 요소 | 원본(맥 앱) | 바뀐 구조(Vercel) |
| --- | --- | --- |
| 실행 환경 | 시연용 Mac 한 대 | Vercel 배포 주소 하나(Next.js) |
| 화면 | SwiftUI + SceneKit | 브라우저(Next.js). 3D는 나중에 붙임 |
| 규칙 엔진(OfficeCore) | Swift 순수 로직 | **TypeScript로 그대로 이식** (`src/lib/office`) |
| 서버 | 없음(앱 안) | Next.js API 라우트 = Vercel 함수 (`src/app/api`) |
| 저장 | `office.json` 한 파일 | **Neon Postgres** `offices` 테이블, 참여자당 JSONB 한 줄 |
| Solar 키 | 앱 설정 폴더의 `.env` | Vercel 환경변수 `UPSTAGE_API_KEY` (브라우저로 보내지 않음) |
| Solar 없을 때 | 기기 안 규칙(PTParser) | **서버 안 규칙**(같은 PTParser를 TS로 이식) |
| 음성 전사 | 앱 안 whisper.cpp | 미정. **글 입력이 기본 경로**, 클라우드 STT는 붙일 자리만 둠(5장) |
| 착석 판정 | Vision(맥 안) | 브라우저 안에서 판정하고 결과(`present/absent/cameraOff`)만 서버로 보냄 |
| 가상 시계 | 앱이 1초마다 진행 | 요청이 올 때 흐른 실제 시간만큼 진행(3장) |

**바뀌지 않은 것**: 출근·지각·결근 후보, 점심 1시간·자리 비움 15분, 18:00 퇴근 점검 분기,
19:00~22:00 추가근무, 이월(처음 날짜 유지·횟수 증가), 보충근무 미이행, 지각비 예상액, '다음 정각' 규칙,
금요일 주간보고, 사내 메일 문구. 원본 시험을 옮겨 같은 결과가 나오는지 확인했다(4장).

## 2. 구조

```
src/
├── lib/office/        규칙 엔진 (화면·DB·네트워크와 무관한 순수 로직)
│   ├── time.ts          KST 날짜·시각, DayKey, Clock
│   ├── rules.ts         근무 규칙 값, 지각비, OfficeError
│   ├── models.ts        업무·초안·허용 시간·근태 기록·메일·주간보고 타입
│   ├── office.ts        Office 상태 기계 (출근 → 아침 PT → 근무 → 점검 → 추가근무 → 퇴근)
│   ├── seat-status.ts   자리 상태와 단계 한 줄 문구
│   ├── mail-templates.ts 사내 메일 문구
│   ├── pt-parser.ts     Solar 없을 때 전사문 → 초안
│   └── organization.ts  조직도 8명
├── lib/solar/         Upstage Solar 클라이언트, 주간보고 기본 답장
├── lib/server/        저장소, 세션(시계 맞추기), 행동 적용, 화면용 상태
└── app/api/           Vercel 함수(라우트)
```

요청 하나의 흐름: **쿠키로 참여자 찾기 → DB에서 상태 읽기 → 가상 시계 맞추기 → 규칙 실행 → 저장 → 화면용 상태 응답**.
규칙을 어기면(예: 출근 전에 업무 확정) 저장하지 않고 409와 한국어 안내 문구를 돌려준다.

## 3. 가상 시계

- 처음 접속하면 **실제 오늘이 속한 주의 월요일 08:55**에서 시작한다(원본과 같음).
- 서버는 계속 떠 있지 않으므로, 요청이 올 때 **마지막 요청 뒤 흐른 실제 시간만큼** 시계를 보낸다.
- 화면은 `GET /api/office`를 **몇 초(권장 5~10초)마다** 불러 시계와 상태를 맞춘다. 초 단위 시계 표시는 화면에서 직접 흘린다.
- **2분 넘게 요청이 없으면** 브라우저를 닫아 둔 것으로 보고 그 사이 시간은 흘리지 않는다(맥 앱을 끄면 시계가 멈추던 것과 같음).
- '다음 정각'은 `skipHour` 행동. 18:00·19:00·22:00 경계에서 멈춘다.

## 4. 확인 방법

```bash
npm install
npm test          # 시험 93개 (원본 시험 이식 + 서버·Solar 시험)
npm run build     # Vercel과 같은 빌드
npm run dev       # http://localhost:3000, DATABASE_URL 없으면 메모리 저장
```

원본 시험과 다르게 한 점: 맥 앱의 `.env` 파일 읽기·쓰기(SolarSettings) 시험은 Vercel 환경변수로 바뀌어 빠졌다.
대신 환경변수 해석 시험을 넣었다.

## 5. 남은 일과 담당 제안

| 순서 | 일 | 메모 |
| --- | --- | --- |
| 1 | **Vercel 프로젝트 연결과 Neon 연결** | Vercel 대시보드 → Storage → Neon 추가하면 `DATABASE_URL`이 자동으로 들어간다. `UPSTAGE_API_KEY`도 환경변수에 추가. 테이블은 첫 요청 때 자동으로 만든다(`db/schema.sql`과 같음). |
| 2 | 화면(프론트) | `docs/backend/API.md`대로 붙인다. 먼저 일반 화면으로 출근 → 아침 PT → 체크리스트 → 퇴근 점검 흐름을 완성하고 3D는 나중에(피드백 권고). |
| 3 | 음성 전사 | 기본은 **글 입력**. 클라우드 STT를 붙이면 결과 글을 `setTranscript` 또는 `/api/office/draft`의 `transcript`로 넣으면 된다. 실패하거나 권한이 없으면 글 입력 화면으로. |
| 4 | 착석 판정 | 브라우저(예: MediaPipe)에서 판정해 상태가 바뀔 때만 `observePresence`로 보낸다. 영상은 서버로 보내지 않는다. 카메라 없이 시연할 때는 버튼으로 같은 값을 보낸다. |
| 5 | 피드백 반영 | 관리 강도 선택, 희망 직무 연결, AI/운영자 역할 정리 등은 규칙 엔진에 기능을 더하는 방식으로(아래). |

### 피드백 반영 상태

| 피드백 | 이번 작업에서 | 다음에 할 일 |
| --- | --- | --- |
| 배포 주소에서 핵심 기능이 되어야 함 | **해결**: 서버를 Vercel 함수로, 저장은 Postgres | 실제 배포 후 주소로 시연 확인 |
| 음성 인식 실패 시 대체 경로 | **해결**: 전사문 직접 입력이 기본 경로, Solar 실패 시 서버 안 규칙 | 클라우드 STT 선택 |
| ERD·상태 값 미정의 | **해결**: `docs/backend/데이터모델.md` | — |
| 카메라 영상 처리 위치 | 브라우저 안 판정, 서버엔 상태 값만 | 화면 안내 문구 |
| 관리 강도 선택, 놓친 날 복귀 | — | `profile`에 강도 설정 추가 후 규칙 분기 |
| 과제와 희망 직무 연결 | — | 초안 생성 시 희망 직무를 Solar에 같이 넘기는 기능 |

## 6. 원본과 일부러 다르게 한 문구

- 초안 출처 "기기 안 규칙으로 정리한 초안" → **"서버 안 규칙으로 정리한 초안 (Solar 미연결)"**
- [인사] 입사 안내 메일의 "이 맥 안에서" → **"영상은 브라우저 안에서만 쓰고 저장하거나 보내지 않습니다." / "글로 옮긴 뒤 녹음은 지웁니다."**
- Solar 키 오류 안내 "설정에서" → **"서버 환경변수에"**
