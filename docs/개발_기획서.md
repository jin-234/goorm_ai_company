# AI 상사 가상회사 · 개발 기획서 (웹 · Vercel 배포판)

> 서울AI디지털배움터 청년AI해커톤 · 팀 **전생했더니 해커톤 엘리트 개발자?**
> 기준 문서: 「가상회사 프로젝트 기획서 (맥 앱판)」의 서비스 기획·규칙·수치를 그대로 따르고,
> 실행 환경만 **맥 앱 한 대 → 배포된 웹 주소(Vercel)** 로 옮긴다.
> 마지막 수정: 2026-11-21 · 상태 표시: ✅ 완료 / 🚧 진행 중 / ⏳ 예정

## 0. 한 줄 요약

**Next.js(App Router) 하나로 화면과 API를 함께 만들어 Vercel에 배포한다.**
규칙(근태·업무·이월·추가근무)은 서버의 TypeScript 규칙 엔진이 계산하고,
LLM(Upstage Solar)은 **아침 PT 체크리스트 구조화**와 **주간보고 답장**만 맡는다.
음성 인식과 착석 판정은 **브라우저 안에서** 처리하고, 실패하면 글 입력·버튼으로 대신한다.
상태는 **Neon Postgres**(Vercel Marketplace)에 참여자당 한 줄로 저장한다.

## 1. 왜 맥 앱에서 웹으로 바꿨나

| 현직자 피드백 | 결정 |
| --- | --- |
| 웹·앱 서버·whisper.cpp를 시연용 Mac 한 대에서 돌리면 **배포 주소로 핵심 기능을 쓸 수 없다**(심사 기준 미충족) | 화면·API를 Vercel에 배포. 로컬 whisper 서버는 두지 않는다. |
| 음성 인식은 클라우드 STT로 바꾸거나 **실패 시 글 입력** 경로 준비 | 브라우저 STT 우선 + 글 입력 항상 제공(5장) |
| ERD·저장소 종류가 없어 상태 변화가 문장으로만 정의됨 | 저장소(Neon Postgres)와 상태 모델·상태 값을 문서화(6장) |
| 3D는 부담이 크니 **출근 → 아침 보고 → 체크리스트 → 퇴근 점검** 흐름을 일반 화면으로 먼저 | 2D 화면 흐름을 먼저 완성하고 3D는 마지막 단계에 입힌다(8장) |
| 마이크·카메라 권한 거부, 전사 지연 시 대기 표시와 글 입력 화면 | 모든 권한 경로에 대체 UI를 둔다(5장) |
| 6시간 안에 STT·Solar·웹캠·3D·메일·규칙을 다 연결해야 함 → **연결 순서 정하기** | 9장 개발 순서와 완료 기준 |

맥 앱에서 검증한 규칙 로직(OfficeCore)·PT 파서·Solar 연동은 **TypeScript로 그대로 이식**했다(시험 93개 통과).

## 2. 개발 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | **Next.js 15 (App Router) + React 19 + TypeScript 5** | 화면과 API(Route Handler)를 한 저장소·한 배포로. Vercel 기본 지원 |
| 런타임 | Vercel Functions, **Node.js 런타임**(Fluid Compute) | Edge 런타임은 쓰지 않는다. Solar 호출은 `maxDuration = 60`초 |
| 배포 | **Vercel** (main → Production, PR → Preview URL) | 심사용 고정 주소, PR마다 미리보기 |
| DB | **Neon Postgres** (Vercel Marketplace) · `@neondatabase/serverless` | 서버리스 HTTP 드라이버라 함수 콜드 스타트에 유리. `DATABASE_URL` 없으면 메모리 저장(로컬 개발) |
| LLM | **Upstage Solar** `solar-pro4` · Chat Completions + Structured Outputs(`json_schema`, strict) | 한국어 성능, 체크리스트를 정해진 JSON으로 받기 |
| 음성 인식(STT) | 1안 **Web Speech API**(`ko-KR`, 브라우저) / 2안 클라우드 STT API(서버 경유) / 항상 **글 입력** | 5.1 참고 |
| 착석 판정 | **MediaPipe Tasks Vision**(`@mediapipe/tasks-vision`, 얼굴·상반신 감지) 브라우저 실행 | 영상이 기기 밖으로 나가지 않음. 서버엔 `present/absent/cameraOff`만 전송 |
| 3D 사무실 | **Three.js + @react-three/fiber (+ drei)** | 2D 흐름 완성 후 입힘. 외부 모델 없이 기본 도형으로(맥 앱 원칙 유지) |
| 시험 | **Vitest** | 규칙 엔진·파서·Solar 클라이언트·서버 흐름 단위 시험 |
| 정적 검사 | `tsc --noEmit` | PR 전 `npm run typecheck && npm test` |

### 쓰지 않기로 한 것
- **whisper.cpp 서버, 로컬 앱 서버**: 배포 주소로 접근 불가.
- **Edge 런타임**: 지원 종료 예정이고 Node API가 필요하다.
- **로그인/회원가입**: 해커톤 범위 밖. 브라우저 쿠키(`office_id`, httpOnly, 1년) 하나로 참여자를 구분한다.

## 3. 시스템 구조

```
┌─────────────────────────── 브라우저 ───────────────────────────┐
│  Next.js 화면 (React)                                          │
│   ├ 출근 화면 ─ 카메라 → MediaPipe(기기 안) → present/absent   │
│   ├ 아침 PT ─ 마이크 → Web Speech API(ko-KR) → 전사문           │
│   │           (권한 거부·미지원·지연 시 → 글 입력)              │
│   ├ 내 책상 / 사내 메일 / 퇴근 점검 / 주간보고                  │
│   └ (마지막) 3D 사무실 · react-three-fiber                      │
│        │  fetch (JSON, 쿠키 office_id)  ·  몇 초마다 GET 폴링  │
└────────┼───────────────────────────────────────────────────────┘
         ▼
┌──────────────── Vercel Functions (Node.js) ───────────────────┐
│  /api/office, /api/office/actions, /draft, /weekly-feedback   │
│     └ withOffice(): 읽기 → 가상 시계 맞추기 → 규칙 실행 → 저장  │
│  규칙 엔진 src/lib/office (순수 TS, 시험 93개)                 │
│  Solar 클라이언트 src/lib/solar ──────────► Upstage API        │
│     실패 시 → PTParser(서버 규칙) / 정해진 문구 기본 답장        │
└────────┼───────────────────────────────────────────────────────┘
         ▼
   Neon Postgres  offices(id, state JSONB, clock_anchor, …)
```

### 가상 시계
- 맥 앱처럼 **실제 시간과 같은 빠르기**로 흐른다. 서버는 계속 떠 있지 않으므로 요청이 올 때 `지금 − clock_anchor` 만큼 시계를 보낸다.
- 2분 넘게 요청이 없으면(브라우저를 닫음) 그 사이 시간은 흘리지 않는다(`CLOCK_PAUSE_AFTER_MS`).
- 시연용 `+1시간(다음 정각)`, `다음 근무일`, `금요일로` 행동으로 시간을 건너뛴다.
- 처음 접속하면 **이번 주 월요일 08:55**에서 시작한다.

### 화면 ↔ 서버 원칙
- 화면은 서버가 준 `officeView`(상태 + 계산된 값 + `can.*` 버튼 가능 여부)만 보고 그린다. **규칙을 화면에서 다시 계산하지 않는다.**
- 규칙 위반은 409 + 한국어 메시지(`OfficeError`), 입력 오류는 400, Solar 오류는 종류별 코드로 돌려준다.

## 4. API 명세

모든 응답은 JSON. 참여자는 쿠키 `office_id`로 구분(없으면 새로 발급).

| 메서드 · 경로 | 상태 | 설명 |
| --- | --- | --- |
| `GET /api/health` | ✅ | 배포 확인. `{ ok, store: "postgres"\|"memory", solar: bool }` |
| `GET /api/office` | ✅ | 지금 회사 상태(`officeView`). 화면이 몇 초마다 불러 시계를 맞춘다 |
| `DELETE /api/office` | ✅ | 처음부터 다시(기록 삭제) |
| `POST /api/office/actions` | ✅ | 행동 하나 적용. 본문 `{ "type": "...", ...값 }` |
| `POST /api/office/draft` | ✅ | 아침 PT 전사문 → 업무 초안. Solar 실패 시 PTParser 초안 + `solarError` |
| `POST /api/office/weekly-feedback` | ✅ | 주간보고 팀장 답장. `{ fallback: true }`면 기본 답장 |
| `GET /api/organization` | ✅ | 조직도(나 + AI 7명), 아침 PT 참석자 |
| `GET /api/solar` · `POST /api/solar` | ✅ | Solar 설정 상태(키 마스킹) · '연결 확인' 핑 |
| `POST /api/stt` | ⏳(2안 선택 시) | 녹음 파일 → 전사문. 4.5MB 본문 제한 안에서(16kHz 모노 Opus, 최대 600초) |

### `actions`의 `type` 목록

| 흐름 | type |
| --- | --- |
| 입사·출근 | `onboard`, `checkIn` |
| 아침 PT | `setTranscript`, `addDraft`, `updateDraft`, `removeDraft`, `confirmTasks` |
| 근무 | `setTaskDone`, `setDeliverable`, `requestLunch`, `registerAway`, `returnFromAllowance`, `observePresence` |
| 퇴근·추가근무 | `submitCheckout`, `endOvertimeEarly`, `submitOvertimeReview` |
| 주간보고 | `saveWeeklyDraft`, `submitWeeklyReport` |
| 메일 | `markMailRead` |
| 시연 시간 | `skipHour`, `startNextWorkday`, `jumpToFriday` |

### Solar 연동 요건 (맥 앱 기획 그대로)
- 기본값: `https://api.upstage.ai/v1` · `solar-pro4` · 30초. `UPSTAGE_BASE_URL/MODEL/TIMEOUT`으로만 바꾼다.
- 체크리스트 스키마: 업무명 · 중요도(1~3) · 마감(HH:MM) · 완료 기준. 없는 값은 `null` → 화면에 **'확인 필요'**.
- 오류 구분: 키 없음, 401 인증 실패, 막힌 키, 403 지역 불일치(→ `kr.api.upstage.ai` 안내), 시간 초과, 429 요청 몰림/월 한도, 4xx 형식 오류, 5xx, 응답 잘림, 응답 해석 실패. **실패해도 전사문·주간보고 초안은 지우지 않는다.**
- 키는 Vercel 환경변수(`UPSTAGE_API_KEY`)로만 넣는다. 화면엔 앞 4자…뒤 4자만.

## 5. 브라우저 기능 (음성·카메라)

### 5.1 아침 PT 음성 인식 ⏳ (담당: 최우진)

| 단계 | 방식 | 비고 |
| --- | --- | --- |
| 1안 (기본) | **Web Speech API** `SpeechRecognition`, `lang = "ko-KR"`, `continuous`, `interimResults` | 서버·비용 없음. Chrome/Edge/Safari 지원, Firefox 미지원. 말하는 동안 전사문이 실시간으로 쌓인다 |
| 2안 (정확도 부족 시) | `MediaRecorder`로 녹음 → `POST /api/stt` → 클라우드 STT | 후보: OpenAI `gpt-4o-transcribe`/Whisper API, 네이버 CLOVA Speech. 키는 서버 환경변수. 녹음은 전사 후 즉시 폐기 |
| 항상 | **글 입력 칸 + '예시 넣기'** | 마이크 거부·미지원 브라우저·전사 지연 모두 이 경로로 끝까지 진행 가능 |

- 전사가 끝나면 바로 `/api/office/draft` 호출, "녹음을 마친 뒤 초안까지 n초" 표시(맥 앱 기준 유지).
- 맥 앱에서 효과를 본 **시작 프롬프트**(3단계 → 2단계 → 1단계 순서 안내)는 화면 안내 문구로 보여 줘 발화 순서를 유도한다.
- 1안/2안 결정 기준: 기획서 예시 PT 3문장을 읽어 **업무명·중요도·마감·완료 기준 4칸이 모두 채워지는지**, 녹음 종료부터 초안까지 **5초 이내**인지.

### 5.2 카메라 출근·착석 판정 ⏳ (담당: 최우진)

- `getUserMedia` → `<video>` → **MediaPipe Face Detector**(+ 필요 시 Pose)로 판정, 신뢰도 0.5 이상이면 사람 있음.
- 맥 앱 수치 그대로: **0.4초 간격(초당 2.5장)**, 2장 연속 보이면 `present`, 마지막으로 보인 뒤 **3초** 지나면 `absent`, 영상이 3초 끊기면 `cameraOff`. 미리보기 좌우 반전.
- **상태가 바뀔 때만** `observePresence`로 서버에 보낸다. 영상·사진은 저장·전송하지 않는다(개인정보 문구로 명시).
- 권한 거부·카메라 없음 → `cameraOff`로 기록하고 "확인한 뒤 근태를 확정합니다" 표시.
- 설정의 **'카메라로 출근과 착석 확인' 끄기** → 출근 버튼 바로 활성화, 내 책상에 '자리에 있음 / 자리 비움 / 카메라 꺼짐' 버튼.

## 6. 데이터 모델 (ERD)

### 6.1 물리 저장: 테이블 1개 ✅

```sql
CREATE TABLE offices (
  id            TEXT PRIMARY KEY,          -- 쿠키 office_id (UUID)
  state         JSONB       NOT NULL,      -- 회사 상태 전체(아래 논리 모델)
  clock_anchor  BIGINT      NOT NULL,      -- 가상 시계를 마지막으로 맞춘 실제 시각(ms)
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**왜 JSONB 한 줄인가**: 규칙 엔진이 상태 전체를 한 번에 읽고 계산해 한 번에 저장하는 구조(맥 앱의 `office.json` 한 파일과 동일)라서, 해커톤 기간엔 정규화보다 **이식 정확도와 트랜잭션 단순함**이 중요하다. 시범 운영 지표 분석(서호균)이 필요해지면 아래 논리 모델 그대로 테이블을 나누거나 JSONB 쿼리로 뽑는다.

### 6.2 논리 모델

```
Office (참여자 1명 = 1행)
 ├ profile: EmployeeProfile        이름, 근무 시작(09:00), 종료(18:00)
 ├ day: WorkDay                     오늘
 │   ├ phase                        (6.3 상태 값)
 │   ├ checkInAt, isLate, absentCandidate
 │   ├ transcript                   아침 PT 전사문
 │   ├ drafts[]: TaskDraft          title, level, due, doneCriteria, carriedFrom
 │   ├ tasks[]: WorkTask            확정 업무 + status(open|done|carried), deliverable
 │   ├ allowances[]: Allowance      kind(lunch|away|dinner), 시작~끝, 사유
 │   ├ awaySpans[]                  unauthorized | cameraOff 구간
 │   └ overtimeOutcome              completed | ranToEnd | abandoned
 ├ history[]: DayRecord             지난 근무일 요약(출근 판정, 업무, 추가근무 결과)
 ├ events[]: AttendanceEvent        근태 기록(checkIn, late, carryOver, supplementMissed …)
 ├ mails[]: Mail                    사내 메일(from/to: me|manager|hr, kind, 답장 출처)
 └ weeklyReports[]: WeeklyReport    완료/미완료/다음 주 목표, replyMailId
```

### 6.3 상태 값

| 대상 | 값 |
| --- | --- |
| 하루 단계 `phase` | `beforeCheckIn` → `morningPT` → `working` → `checkoutReview` → (`dinner` → `overtime` → `overtimeReview`) → `off` |
| 업무 `status` | `open` / `done` / `carried` |
| 업무 중요도 `level` | 1 이월 가능 / 2 당일 완료 / 3 필수 마감 |
| 출근 판정 | `onTime` / `late`(09:01부터) / `absentCandidate`(출근 없이 18:00 경과) |
| 착석 `presence` | `present` / `absent` / `cameraOff` / `unknown` |
| 추가근무 결과 | `completed` / `ranToEnd` / `abandoned`(보충근무 미이행) |
| 초안 출처 | `solar` / `localRules` / `manual` |
| 답장 출처 | `solar` / `localTemplate` |

### 6.4 핵심 규칙 (규칙 엔진에서만 계산)
- 점심 1시간(하루 1회, 메일 요청 후 수락), 자리 비움 건당 15분, 허용 시간 초과 시 '근무 중 자리 비움'.
- 18:00 퇴근 점검: 1단계 미완료 → 이유·계획 보고 후 이월 / 2·3단계 → 18~19시 저녁, **19~22시 추가근무 한 구간**(3단계 먼저) / 22:00 미완료 → 이월.
- 확정 업무 없이 18:00 → '아침 PT 미진행'. 추가근무 중도 종료 → '보충근무 미이행'.
- 지각비 예상액: 지각 1점·결근 후보 3점, 월 2점까지 0원, 초과 1점당 1,000원, 월 최대 5,000원(시연에선 표시만).

## 7. 화면 구성 ⏳ (프론트엔드)

현직자 디자인 피드백을 반영해 **3D 없이도 흐름이 완결되는 2D 화면**을 먼저 만든다.

| 화면 | 내용 | 주요 API |
| --- | --- | --- |
| 상단 막대(고정) | 가상 시각·날짜, 지금 단계, **지금 해야 할 일 + 실행 버튼**, 지각 점수·예상액, `+1시간` | `GET /api/office` |
| 입사 | 이름 입력, 카메라 사용 여부 | `onboard` |
| 출근 | 카메라 미리보기, 착석 확인 후 출근 버튼 | `checkIn`, `observePresence` |
| 회의실 · 아침 PT | 발표 양식, 말하기/글 입력, 체크리스트 표(빈 칸 '확인 필요'), 확정 | `setTranscript`, `/draft`, `*Draft`, `confirmTasks` |
| 내 책상 | 업무 목록(**'오늘 꼭 할 일'** 같은 행동형 이름), 완료 체크·결과물 링크, 점심·자리 비움 | `setTaskDone`, `setDeliverable`, `requestLunch`, `registerAway` |
| 사내 메일 | 받은 메일, 지각·이월·추가근무 안내, 팀장 답장 | `markMailRead` |
| 퇴근 점검 | 1단계 이유·계획 입력, 2·3단계 추가근무 배정 — **이유와 선택 가능한 행동** 함께 표시 | `submitCheckout`, `endOvertimeEarly`, `submitOvertimeReview` |
| 하루 마무리 | **완료한 일과 다음 날 계획을 균형 있게** | `startNextWorkday` |
| 주간보고(금) | 3칸 작성(초안 보존), 제출 후 답장, 실패 시 '다시 시도/기본 답장 받기/설정' | `saveWeeklyDraft`, `submitWeeklyReport`, `/weekly-feedback` |
| 설정 | Solar 연결 확인, 카메라 끄기, 처음부터 다시 | `/api/solar`, `DELETE /api/office` |

접근성(맥 앱 기준 유지): 본문 15px 이상, 제목 22~24px, 버튼 높이 36~40px, 경고는 색+아이콘+글자, 이모지 없음, 한국어.

## 8. 3D 사무실 ⏳ (마지막 단계)

- react-three-fiber로 맥 앱 SceneKit 장면을 단순화해 옮긴다: 사무실·회의실·탕비실, 캐릭터 8명(나 + AI 7명).
- 1차 범위: **장소 클릭 → 해당 2D 패널 열기**, 시각에 따른 조명(09:00 / 20:00 두 컷), 내 캐릭터의 착석/자리 비움 표시.
- 2차(시간 남으면): 동료 출퇴근·점심 이동, 자리 비움 사유별 이동.
- 각 공간에 **이름표**를 붙인다(피드백). 3D가 늦어지면 2D 화면만으로 시연한다.

## 9. 개발 순서와 완료 기준

| # | 단계 | 상태 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | Next.js 프로젝트 세팅 | ✅ | `npm run build` 통과 |
| 2 | 규칙 엔진(OfficeCore) TS 이식 | ✅ | 출근·지각·점심·자리 비움·18시 분기·추가근무·이월·지각비 시험 통과 |
| 3 | PTParser 이식 | ✅ | 예시 PT → 3단계·15:00·"오탈자를 확인하고 제출본을 저장" |
| 4 | Solar 연동 | ✅ | 체크리스트·주간 답장·연결 확인, 오류 종류별 메시지 |
| 5 | API 라우트 + 저장소(Neon/메모리) | ✅ | `vitest` 93개 통과, `/api/health`에서 `store: "postgres"` |
| 6 | **Vercel 배포 + Neon 연결** | 🚧 | Preview/Production URL에서 `/api/health` 정상, 환경변수 설정 |
| 7 | 2D 화면: 출근 → 아침 PT(글 입력) → 체크리스트 확정 → 퇴근 점검 | ⏳ | 배포 주소에서 마이크·카메라 없이 하루 흐름 끝까지 |
| 8 | 사내 메일·점심·자리 비움·추가근무·주간보고 화면 | ⏳ | 금요일 답장까지 끊김 없음 |
| 9 | 음성 인식(Web Speech) | ⏳ | 예시 PT 4칸 채움, 초안까지 5초 이내, 거부 시 글 입력 |
| 10 | 카메라 착석 판정(MediaPipe) | ⏳ | 앉음/떠남/가림 3가지가 3초 안에 반영, 끄기 설정 동작 |
| 11 | 3D 사무실 | ⏳ | 장소 클릭으로 패널 열기, 09:00·20:00 조명 |
| 12 | 시연 리허설 | ⏳ | 배포 주소에서 3분 시연 대본 통과 |

**원칙**: 각 단계는 배포 주소에서 확인된 뒤 다음으로 넘어간다. 7단계가 끝나면 그 시점부터 언제든 시연 가능해야 한다.

## 10. 환경변수와 배포

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `UPSTAGE_API_KEY` | 권장 | 없으면 서버 규칙(PTParser)·기본 답장으로 동작 |
| `UPSTAGE_BASE_URL` / `UPSTAGE_MODEL` / `UPSTAGE_TIMEOUT` | 선택 | 기본 `https://api.upstage.ai/v1` · `solar-pro4` · 30초 |
| `DATABASE_URL` | 배포 시 필수 | Vercel Marketplace에서 Neon 연결 시 자동 주입. 없으면 메모리 저장 |
| (2안 선택 시) STT 키 | 선택 | `/api/stt`에서만 사용 |

- 배포: `main` 머지 → Production, PR → Preview. 환경변수는 Vercel 대시보드 또는 `vercel env`로 관리, `.env`는 커밋하지 않는다.
- 함수 제약: 요청·응답 본문 4.5MB, Solar 라우트 `maxDuration = 60`.
- 확인: 배포 후 `/api/health` → `{ ok: true, store: "postgres", solar: true }`.
